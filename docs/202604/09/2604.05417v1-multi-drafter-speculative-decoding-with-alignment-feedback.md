## 摘要
投机解码 (SD) 通过使用较小的模型来起草未来的 token，并由目标大语言模型 (LLM) 进行验证，从而加速 LLM 的推理过程。通过仅接受对齐的 token，该方法能够保持生成质量。然而，通常针对特定任务或领域训练的单个草稿模型在多样化应用中表现出的有效性有限。为了解决这一问题，我们提出了 MetaSD，这是一个将多个草稿模型集成到 SD 过程中的统一框架。MetaSD 通过利用对齐反馈并将草稿模型选择建模为多臂老虎机问题，动态地为异构草稿模型分配计算资源。大量实验表明，MetaSD 的性能始终优于单草稿模型方法。

## Abstract
Speculative decoding (SD) accelerates large language model (LLM) inference by using a smaller model to draft future tokens, which are then verified by the target LLM. This preserves generation quality by accepting only aligned tokens. However, individual drafters, often trained for specific tasks or domains, exhibit limited effectiveness across diverse applications. To address this, we introduce \textsc{MetaSD}, a unified framework that integrates multiple drafters into the SD process. MetaSD dynamically allocates computational resources to heterogeneous drafters by leveraging alignment feedback and framing drafter selection as a multi-armed bandit problem. Extensive experiments show MetaSD consistently outperforms single-drafter approaches.

**研究动机与背景：**
投机解码（Speculative Decoding, SD）是加速大语言模型（LLM）推理的主流技术，其核心是利用一个小模型（Drafter）预测后续 token，再由大模型（Target LLM）并行验证。然而，现有的 SD 方法大多依赖**单一草稿模型**。由于单一模型通常在特定领域训练，面对多样化的用户查询（如从写代码切换到翻译）时，其预测准确率（接受率）会大幅下降，导致加速效果受限。

**核心问题：**
如何在推理过程中，从多个异构的专业化草稿模型中动态、高效地选择最匹配当前上下文的那一个，以实现跨任务的稳健加速？

### 2. 论文提出的方法论：MetaSD
**核心思想：**
将多草稿模型选择问题建模为**多臂老虎机（Multi-Armed Bandit, MAB）**问题。在每一轮投机解码中，系统根据历史表现选择一个草稿模型，并利用大模型的验证结果作为“对齐反馈”来更新选择策略。

**关键技术细节：**
*   **对齐反馈作为奖励信号：** 提出了**块散度（Block Divergence, BD）**作为奖励函数。相比于传统的“块效率（BE，即接受 token 的数量）”，BD 利用了 token 概率分布的总体变分距离（TV Distance）。
*   **MetaSD-UCB 算法：** 采用置信区间上界（UCB）策略平衡“探索”（尝试表现未知的草稿模型）与“利用”（使用已知表现最好的模型）。
*   **理论保证：** 论文证明了 MetaSD-UCB 在目标序列长度 $B$ 下具有对数级的悔值（Regret）上界，且证明了 BD 奖励比 BE 奖励具有更小的方差和更强的信号强度。
*   **架构兼容性：** 支持“黑盒”模式（独立的小模型，如 Speculative Sampling）和“白盒”模式（集成在目标模型头部的草稿器，如 Eagle）。

### 8. 不足与局限
*   **显存扩展性：** 虽然单个小模型占用显存低，但如果草稿模型数量增加到几十个甚至上百个，显存占用和模型切换的 I/O 开销可能会变得显著。
*   **依赖草稿器质量：** 如果候选池中所有的草稿模型对当前任务的预测都很差，MetaSD 依然无法突破性能瓶颈。
*   **批处理复杂性：** 目前主要针对单序列推理，在多任务混合的大规模批处理（Batch Inference）场景下，如何高效调度多个草稿模型仍需进一步探索。
