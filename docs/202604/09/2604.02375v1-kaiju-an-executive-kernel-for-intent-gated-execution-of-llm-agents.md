## 摘要
基于大语言模型并使用 ReAct 模式的工具调用自主智能体表现出三个局限性：串行延迟、上下文二次方增长，以及易受提示词注入和幻觉的影响。近期的工作趋向于将规划与执行分离，但在每种情况下，模型仍与执行机制耦合。我们为大语言模型智能体引入了一种系统级抽象，将智能体工作流的执行与大语言模型推理层解耦。我们定义了两个一等抽象：（1）意图门控执行（IGX），一种在执行时强制执行意图的安全范式；（2）执行内核，负责管理调度、工具分发、依赖解析、故障处理和安全。在 KAIJU 中，大语言模型预先进行规划，通过感知依赖的参数注入，乐观地并行调度工具。工具通过 IGX 基于四个独立变量进行授权：范围、意图、影响和许可（外部批准）。KAIJU 支持三种自适应执行模式（Reflect、nReflect 和 Orchestrator），提供逐渐细粒度的执行控制，适用于复杂的调查、深度分析或研究。与 ReAct 基准的实证评估表明，由于规划开销，KAIJU 在简单查询上存在延迟惩罚，在复杂度适中时趋于一致，而在需要并行数据采集的计算查询上具有结构性优势。除了延迟之外，这种分离还强制执行了 ReAct 仅通过提示词无法实现的行为保证。代码可在 https://github.com/compdeep/kaiju 获取。

## Abstract
Tool-calling autonomous agents based on large language models using ReAct exhibit three limitations: serial latency, quadratic context growth, and vulnerability to prompt injection and hallucination. Recent work moves towards separating planning from execution but in each case the model remains coupled to the execution mechanics. We introduce a system-level abstraction for LLM agents which decouples the execution of agent workflows from the LLM reasoning layer. We define two first-class abstractions: (1) Intent-Gated Execution (IGX), a security paradigm that enforces intent at execution, and (2) an Executive Kernel that manages scheduling, tool dispatch, dependency resolution, failures and security. In KAIJU, the LLM plans upfront, optimistically scheduling tools in parallel with dependency-aware parameter injection. Tools are authorised via IGX based on four independent variables: scope, intent, impact, and clearance (external approval). KAIJU supports three adaptive execution modes (Reflect, nReflect, and Orchestrator), providing progressively finer-grained execution control apt for complex investigation and deep analysis or research. Empirical evaluation against a ReAct baseline shows that KAIJU has a latency penalty on simple queries due to planning overhead, convergence at moderate complexity, and a structural advantage on computational queries requiring parallel data gathering. Beyond latency, the separation enforces behavioural guarantees that ReAct cannot match through prompting alone. Code available at https://github.com/compdeep/kaiju

*   **串行延迟与效率低下**：ReAct 采用“思考-行动-观察”的循环，工具调用是串行的，导致任务耗时随步骤线性增长。

**KAIJU** 的核心目标是通过**解耦推理层与执行层**，建立一个类似操作系统的“执行内核”，实现并行化、低成本且结构化安全的智能体执行环境。

### 2. 方法论：核心思想与关键技术
KAIJU 引入了两个核心抽象概念：

*   **执行内核（Executive Kernel）**：
    *   **预先规划与并行调度**：LLM 首先生成一个有向无环图（DAG）计划。内核根据依赖关系（Depends-on）自动并行触发无依赖的工具。
    *   **参数注入机制（Param Refs）**：允许在规划阶段定义数据流（如步骤 B 使用步骤 A 的某个 JSON 字段），在运行时自动解析注入，无需 LLM 介入中间数据传递。
    *   **自适应执行模式**：
        *   *Reflect*：在波次（Wave）间进行反思，决定是否重规划。
        *   *nReflect*：每完成 N 个节点进行一次反思。
        *   *Orchestrator*：最精细模式，每个节点完成后都有轻量级观察者评估。

*   **意图门控执行（IGX）**：
    这是一个四变量安全模型，公式化表达为：$t \in S \land I(t, p) \leq \min(\sigma, c_s) \land C(t, p, u) = \text{allow}$。
    1.  **Scope (范围)**：允许调用的工具白名单。
    2.  **Intent (意图)**：由外部系统（非 LLM）设定的操作权限等级（如观察级、操作级、覆盖级）。
    3.  **Impact (影响)**：工具作者定义的静态影响等级（只读=0，写入=1，删除=2）。
    4.  **Clearance (许可)**：调用外部 HTTP 端点进行实时资源级授权（如地理围栏检查）。
    *关键点*：门控决策对 LLM 不可见，防止模型通过试错绕过安全策略。

### 6. 主要结论与发现
*   **延迟优势**：在简单任务上，KAIJU 因规划开销略慢于 ReAct；但在复杂任务和计算任务上，KAIJU 的速度比 ReAct 快 2-3 倍（如计算任务 25.2s vs 43.7s）。
*   **可靠性**：在天文学基准测试中，KAIJU 模式全部完成（10/10），而 ReAct 因上下文耗尽失败了 2 场。
*   **上下文优化**：KAIJU 将上下文复杂度从 $O(n^2k)$ 降低到接近线性 $O(nk)$，有效避免了长任务中的性能退化。
*   **安全增强**：IGX 成功阻止了恶意或高风险调用，且由于 LLM 无法观察到拒绝原因，消除了自适应攻击面。

### 7. 优点
*   **架构解耦**：将“思考”与“执行机制”分离，使智能体更像一个受控的软件系统而非失控的脚本。
*   **结构化安全**：IGX 不依赖提示词，提供了确定性的安全保障。
*   **鲁棒性**：通过微规划器（Micro-Planner）实现节点级故障恢复，无需人工干预。
*   **数据流透明**：参数注入机制解决了并行任务间的数据依赖问题。

### 8. 不足与局限
*   **规划开销**：对于极简单的查询，预先规划显得多余且增加了首字延迟。
*   **规划器依赖**：系统的上限取决于规划器 LLM 的分解能力，如果初始计划极差，虽然有反思补偿，但会增加延迟。
*   **动态影响评估**：对于 Shell 等通用工具，其影响等级（Impact）依赖正则匹配，可能存在漏报或误报风险。
*   **应用限制**：目前主要针对结构化工具调用，对于需要极高实时交互、非结构化探索的任务，DAG 模式可能不如对话模式灵活。
