## 摘要
部署在智能体环境中的大语言模型（LLMs）必须在不同的任务实例中运用多种能力，其中“能力”被定义为在轨迹中执行一个或多个动作，这些动作对于成功解决环境中的子集任务至关重要。许多现有方法要么依赖于并非针对模型在目标环境中实际能力缺陷的合成训练数据，要么直接在目标环境上进行训练，导致模型需要跨任务隐式地学习这些能力。我们提出了 TRACE（将智能体循环失败转化为面向能力的训练环境），这是一个用于特定环境智能体自我提升的端到端系统。TRACE 通过对比成功与失败的轨迹来自动识别缺失的能力，并为每种能力合成一个针对性的训练环境，根据是否运用了该能力提供奖励，随后在每个合成环境上通过强化学习（RL）训练 LoRA 适配器，并在推理时路由至相关的适配器。实验结果表明，TRACE 在不同环境中具有良好的泛化性，在 $τ^2$-bench（客服场景）上比基础智能体提升了 14.1 分，在 ToolSandbox（工具使用场景）上增加了 7 个满分，分别比最强基准模型高出 7.4 分和 4 个满分。在相同数量的采样（rollouts）下，TRACE 的扩展效率优于基准模型，在 $τ^2$-bench 上分别超过 GRPO 和 GEPA 9.2 分和 7.4 分。

## Abstract
Large Language Models (LLMs) deployed in agentic environments must exercise multiple capabilities across different task instances, where a capability is performing one or more actions in a trajectory that are necessary for successfully solving a subset of tasks in the environment. Many existing approaches either rely on synthetic training data that is not targeted to the model's actual capability deficits in the target environment or train directly on the target environment, where the model needs to implicitly learn the capabilities across tasks. We introduce TRACE (Turning Recurrent Agent failures into Capability-targeted training Environments), an end-to-end system for environment-specific agent self-improvement. TRACE contrasts successful and failed trajectories to automatically identify lacking capabilities, synthesizes a targeted training environment for each that rewards whether the capability was exercised, and trains a LoRA adapter via RL on each synthetic environment, routing to the relevant adapter at inference. Empirically, TRACE generalizes across different environments, improving over the base agent by +14.1 points on $τ^2$-bench (customer service) and +7 perfect scores on ToolSandbox (tool use), outperforming the strongest baseline by +7.4 points and +4 perfect scores, respectively. Given the same number of rollouts, TRACE scales more efficiently than baselines, outperforming GRPO and GEPA by +9.2 and +7.4 points on $τ^2$-bench.

### TRACE: 面向能力的针对性智能体训练论文总结

#### 1. 核心问题与整体含义
论文针对的核心问题是：**大语言模型（LLM）智能体在复杂任务中往往因为缺乏某些特定能力（如数据推理、工具调用精度等）而失败，但现有的训练方法效率低下。**
*   **研究动机：** 直接在目标环境进行强化学习（RL）存在奖励稀疏、难以进行信用分配（Credit Assignment）的问题；而使用通用的合成数据训练又缺乏针对性，无法解决模型在特定环境下的具体短板。
*   **整体含义：** 提出了一种名为 **TRACE** 的端到端系统，通过分析模型自身的失败案例，自动识别能力缺陷，并“对症下药”地构建合成训练环境进行强化学习，从而实现高效的自我进化。

#### 2. 方法论
TRACE 的核心思想是将复杂的任务拆解为具体的能力点，其流程包含四个关键步骤：
1.  **对比式能力识别（Contrastive Identification）：** 
    *   收集模型在目标环境中的成功和失败轨迹。
    *   利用 LLM 分析器对比两类轨迹，识别出导致失败的关键能力缺口（如“结构化数据推理”）。
    *   通过“对比间隙（Contrastive Gap）”和“失败覆盖率”指标对能力进行排序，优先训练高影响力的能力。
2.  **能力针对性环境合成（Environment Synthesis）：** 
    *   为每个识别出的能力缺陷自动生成一个专门的合成训练环境（$E_{cs}$）。
    *   该环境保留目标环境的工具接口，但任务设计专门为了测试该特定能力，并提供程序化的密集奖励信号。
3.  **强化学习训练：** 
    *   在每个合成环境上，使用 **GRPO（群组相对策略优化）** 算法训练独立的 **LoRA 适配器**。
    *   这种方式避免了全参数微调的开销，且能保持基础模型的稳定性。
4.  **能力组合与路由（Routing）：** 
    *   在推理阶段，使用基础模型作为路由器，根据当前任务描述选择最匹配的 LoRA 适配器进行激活。

#### 3. 实验设计
*   **数据集/场景：**
    *   **$\tau^2$-Bench：** 模拟真实的客户服务场景（航空和零售领域），涉及复杂的工具交互和用户策略。
    *   **ToolSandBox：** 一个状态化的工具使用基准测试，侧重于权限错误恢复和时间推理等能力。
*   **对比方法：**
    *   **Base Model：** 未经针对性训练的基础模型（Qwen3-30B）。
    *   **GRPO on Target：** 直接在目标环境上进行强化学习。
    *   **ADP / AWM：** 使用大规模通用智能体轨迹或通用合成环境进行训练的先进基线。
    *   **GEPA：** 一种基于进化算法的提示词（Prompt）优化方法。

*   **硬件设备：** 使用了 **4 至 8 台 NVIDIA A100-80GB GPU**。
*   **模型规模：** 基础模型和模拟器均采用 **Qwen3-30B-A3B-Instruct**。
*   **训练细节：** 每个能力适配器更新约 5.3% 的参数，训练循环最多进行 40 次迭代。
*   **时间成本：** 自动分析阶段约需 5 分钟，相比整体训练时间几乎可以忽略。

#### 5. 实验数量与充分性
*   **实验规模：** 论文在两个主流基准测试上进行了详尽测试，并针对 $\tau^2$-Bench 的不同领域（航空、零售）分别报告了结果。
*   **消融实验：** 进行了多项消融研究，包括：
    *   不同能力数量对性能的影响（Scaling with capabilities）。
    *   不同采样数量下的性能表现（Scaling with rollouts）。
    *   路由策略与模型合并（Merging）、蒸馏（Distillation）等其他组合方式的对比。

#### 6. 主要结论与发现
*   **性能显著提升：** TRACE 在 $\tau^2$-Bench 上比基础模型提升了 **14.1%** 的成功率，在 ToolSandBox 上增加了 **7 个** 满分案例，显著优于所有基线。
*   **扩展效率极高：** 在相同的采样次数下，TRACE 的表现远超直接 RL 训练和提示词优化，且性能随采样数呈单调增长，未出现基线方法中的不稳定性。
*   **针对性训练的必要性：** 实验证明，仅仅在提示词中加入能力描述（GEPA）是不够的，通过 RL 显式地训练模型执行这些能力至关重要。
*   **路由优于合并：** 采用独立的 LoRA 适配器并通过路由切换，比将多个能力合并到单个模型中效果更好，避免了能力间的干扰。

#### 7. 优点
*   **精准诊断：** 引入对比分析机制，能够自动定位模型“为什么失败”，而不是盲目增加训练数据。
*   **模块化设计：** 使用 LoRA 适配器和路由机制，使得系统易于扩展，且不会破坏模型原有的通用能力。
*   **自动化程度高：** 从失败分析到环境生成再到训练，实现了闭环的自我改进。
*   **数据效率：** 通过合成针对性环境，用较少的数据就达到了超越大规模通用预训练的效果。

#### 8. 不足与局限
*   **推理延迟：** 推理时需要先进行一次路由分类，虽然开销较小，但仍增加了额外的延迟。
*   **能力定义的依赖：** 系统的有效性高度依赖于 LLM 分析器能否准确识别和描述能力缺口，若分析器本身存在偏差，可能导致合成环境偏离目标。
*   **适配器管理：** 随着识别出的能力越来越多，维护和存储大量的 LoRA 适配器可能会带来管理上的复杂性。
*   **场景覆盖：** 目前主要在工具使用和客服场景验证，对于需要极长程规划或开放式创造的任务（如完整软件工程项目）尚需进一步验证。
