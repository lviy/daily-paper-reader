## 摘要
现代智能体工作流将复杂任务分解为专门的子任务，并将其路由到不同的模型，以便在不牺牲质量的前提下最大限度地降低成本。然而，目前的路由架构仅专注于性能优化，未能记录模型能力与成本之间的潜在权衡。由于缺乏清晰的依据，开发人员无法区分“智能效率”（即针对合适任务使用专门模型）与“预算驱动的模型选择所导致的潜在失败”。我们提出了 Topaz，这是一个为智能体路由引入正式可审计性的框架。Topaz 用一种内在可解释的路由器取代了静默的模型分配，该路由器包含三个组件：(i) 基于技能的画像，将不同基准测试中的性能综合为细粒度的能力画像；(ii) 完全可追溯的路由算法，利用基于预算的多目标优化，生成关于技能匹配得分如何与成本进行权衡的清晰轨迹；(iii) 面向开发者的解释，将这些轨迹转化为自然语言，允许用户审计系统逻辑并迭代调整成本与质量的权衡。通过使路由决策具有可解释性，Topaz 使用户能够理解、信任并有效地引导路由智能体系统。

## Abstract
Modern agentic workflows decompose complex tasks into specialized subtasks and route them to diverse models to minimize cost without sacrificing quality. However, current routing architectures focus exclusively on performance optimization, leaving underlying trade-offs between model capability and cost unrecorded. Without clear rationale, developers cannot distinguish between intelligent efficiency -- using specialized models for appropriate tasks -- and latent failures caused by budget-driven model selection. We present Topaz, a framework that introduces formal auditability to agentic routing. Topaz replaces silent model assignments with an inherently interpretable router that incorporates three components: (i) skill-based profiling that synthesizes performance across diverse benchmarks into granular capability profiles (ii) fully traceable routing algorithms that utilize budget-based and multi-objective optimization to produce clear traces of how skill-match scores were weighed against costs, and (iii) developer-facing explanations that translate these traces into natural language, allowing users to audit system logic and iteratively tune the cost-quality tradeoff. By making routing decisions interpretable, Topaz enables users to understand, trust, and meaningfully steer routed agentic systems.

### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）应用从单一模型转向复杂的**智能体工作流（Agentic Workflows）**，开发者通常采用“模型路由”策略：将简单任务交给廉价模型，复杂任务交给昂贵的尖端模型，以平衡成本与性能。
然而，现有的路由系统（如 FrugalGPT、RouteLLM 等）大多是**黑盒决策**。开发者无法得知系统为何选择某个模型，难以区分这是“合理的效率优化”还是“为了省钱而牺牲质量的潜在失败”。这种缺乏透明度的现状导致开发者在调试失败的工作流时无从下手，只能盲目信任或放弃路由。

### 2. 方法论：Topaz 框架
Topaz 旨在构建一个**内在可解释（Inherently Interpretable）**的路由框架，其核心思想是将路由决策建立在可量化的“技能匹配”和“成本权衡”之上。

*   **技能画像（Skill-Based Profiling）：**

    *   **任务端：** 利用 LLM 分析工作流中的子任务，提取其技能需求、复杂度和质量敏感度。
*   **可追溯路由算法：**
    *   **目标导向路由：** 通过公式计算“技能匹配度”与“成本惩罚”的加权权衡。开发者可以调节全局成本敏感度参数。
    *   **预算导向路由：** 使用动态规划（DP）算法，在给定的总预算约束下，最大化整个工作流的加权质量得分。
*   **自然语言解释生成：**
    *   系统记录路由过程中的中间计算数值（如匹配分、成本差），并利用 LLM 将这些数值轨迹转化为面向开发者的自然语言解释，说明为何选择 A 模型而非 B 模型。

### 6. 主要结论与发现
*   **动态适应性：** Topaz 能根据开发者设定的成本偏好灵活切换模型。例如，在成本敏感时，它能准确识别出哪些任务可以由 Mistral 胜任，而将预算留给关键的“技术诊断”任务。
*   **解释的忠实性：** 生成的自然语言解释能够准确反映底层的数值权衡（如“Gemini 虽好但太贵，Mistral 的摘要能力已足够”），避免了传统 XAI 的事后强行解释（Post-hoc rationalization）。
*   **技能饱和识别：** 发现某些简单任务在低端模型上已达到“能力饱和”，此时升级到昂贵模型并无边际收益，Topaz 能有效识别并节省这部分开支。

### 7. 优点
*   **高透明度：** 将“黑盒”路由变成了“白盒”，提供的解释具有可操作性，方便开发者微调。
*   **领域无关性：** 技能画像方法不依赖特定模型，可以轻松扩展到新发布的 LLM 或新的基准测试。
*   **闭环反馈：** 引入了用户反馈机制，允许开发者手动调整任务的“质量敏感度”，从而引导路由器的后续行为。

### 8. 不足与局限
*   **画像依赖性：** 路由效果高度依赖于公开基准测试的准确性和 LLM 画像器的判断。如果基准测试存在数据污染或画像器理解有误，路由决策会受影响。
*   **静态画像风险：** 模型能力随 API 更新可能发生变化，静态画像需要定期维护。
*   **下游行为未解释：** Topaz 解释的是“为什么选这个模型”，但无法解释“选中的模型为什么输出了错误结果”，它只解决了路由层的透明度问题。
*   **Token 预测误差：** 成本估算依赖于对输入/输出 Token 长度的预测，而这在实际生成前往往是不准确的。
